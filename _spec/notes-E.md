## 2. 观势：精确窗口

| 项 | 值 |
|---|---|
| 进入 | 按下 guard 的**当帧**生效（不设长按延迟，格挡不能有入场延迟） |
| 时间缩放 | 0.35×，每帧挂 `slowmo(0.35, 0.034)`（2 帧） |
| 松手恢复 | **2 帧（33ms）** 回到 1.0×，长按 300 帧后不堆积 |
| 耗墨 | 实测 **11.8/s**（游戏时间）。因为观势中 dt 被缩放，真实时间约 **4.1/s** |
| 完美观势窗口 | **`p.parryWindow === p.observing`**，整个观势期间都算 |
| 格挡收益 | 不掉血 + 墨 **+18** + 敌人硬直 **0.9s** + `Tech.gain(moveId, 34)` |
| 挨打收益 | 掉血 + `Tech.gain(moveId, 12)` |
| 守势型（`danger:false`） | 观势累计读到 **dur 的 50%** 时给一次 34，一个 telegraph 只给一次 |

**没有加 spec 之外的限制**：不要求朝向正确、退出观势没有硬直。观势的代价是墨 + 时间被自己也拖慢（周围其他敌人照样打你），不需要再加惩罚。

观势中按 J 会**当帧退出观势并出剑**（实测 `st=atk1 obs=false`），不吃后摇。

## 5. 给 F 的建议：telegraph 该留多长才公平

**结论：普通杂兵 0.55–0.70s，必须观势才能过的招 ≥0.70s，不打算让人格挡的骚扰招 0.35–0.45s，`danger:true` 绝不低于 0.30s。**

推导：进入观势是**当帧**生效，所以玩家需要的只是「看到 → 按下 K」的反应时间。但**在玩家按下 K 之前，时间是 1.0× 的**（慢镜是观势的结果，不是前提），所以留给反应的真实时间就等于 telegraph 时长本身。人的选择反应约 300–400ms，因此：

- **< 0.30s**：不可反应，等于背板。§3.2 说 0.35–0.8s，请不要突破下限。
- **0.35–0.45s**：可以用，但只用在「打中了也不太疼」的骚扰招上，当作节奏噪音。
- **0.55–0.70s**：**默认档**。第一次见能反应过来，练熟后从容。
- **≥0.70s**：Boss 的「必须观势」招。同时请把 `path` 画得和该 Boss 其他招明显不同——观势时玩家读的就是这条线的形状。

另外三条：

1. **同一敌人两次 telegraph 之间至少留 0.9s 空档。** 格挡成功给敌人 0.9s 硬直，这 0.9s 就是玩家的惩罚窗口；主角三连全程 0.62s（37 帧），刚好塞得下一套完整连段。空档小于 0.9s 会让「格挡成功」没有正反馈。
2. **多敌同屏时错开 telegraph。** 观势是全局慢镜，玩家一次只能读一条线；两条同时亮起会让人放弃观势。
3. **`danger:false` 的守势 telegraph 请给足 1.0–1.2s**，因为要观势读满 50% 才给进度。守阁人用的 1.2s 是验证过的。

### telegraph 的 `path` 坐标约定（**F 必须和我一致**）
```
绝对点 = [ owner.cx() + px * owner.facing , owner.cy() + py ]
```
即：**相对 owner 中心、x 按 facing 镜像、y 向下为正**。已报 Lead 裁定（决议待回）。写反了轨迹会画到反方向去。

### 颜色是免费的一句话
`danger:true` → 朱砂；`danger:false` → 石青。玩家不需要读文字就知道「这条会打人 / 这条只是架势」。F 不要自己传 `color` 覆盖它，除非有特别理由。

## 6. 我在 combat.js 里做了、F 不要重复做的事

1. **命中三件套是 combat 的统一出口**：任何一次 `SJ.Combat.hit` 命中都会自动产生
   hitstop + 屏幕震 + 墨点飞溅 + 挥毫弧线 + 音效。F 只要传 `weight:'light'|'mid'|'heavy'|'huge'`
   （不传就按伤害自动分档），**不要自己调 `slowmo`/`shake`/`splash`**，会叠加成一团糊。
2. **点燃 DoT**：hitbox 传 `type:'fire'` 就会自动挂 2.5s 燃烧（3 伤/秒）。已在 combat 内实现。
3. **硬直**：`SJ.Combat.stun(ent, sec, src)`，内部走 `ent.hurt(0, src, {stun, parried:true})`，
   **不新增字段**，复用 F 本来就要处理的 `opt.stun`。
4. 同一个 hitbox 对同一目标只结算一次（`hb.struck`）。`pierce:true` 才会继续打后面的目标。
5. `SJ.Combat.lastFoeMove` 由 combat 维护（敌招打中或被格挡玩家时写入），说剑读它。

**给 F 的一个坑（刺客·瞬移会踩到同一个）**：直接写 `e.x/e.y` 做瞬移，落点在墙里会把实体卡死 ——
`World.moveX/moveY` 只在「移动过程中」推出，已经重叠了推不出来。
`tech.js` 里的 `blink(p, tx, ty)` 是解法：沿原路 6 档回退，找第一个不重叠的落点，全都不行就原地不动。
实测把敌人贴到右墙内侧再放孤影，落点 `insideSolid=false`，正常场合仍然穿到敌人背后并回头。

## 7b. 决议 007 / 009 追加的三个接口（已实现并实测）

### `SJ.Player.setSlot(i, moveId)` — 招式槽的唯一写入者（H 调用）
同时写 `p.slots[i]` 与 `SJ.Save.data.slots[i]` 并 `SJ.Save.save()`。
- 传没学会的招 → 返回 `false`，不写入
- 同一招不能占两个槽：换槽时自动从旧槽摘掉
- 实测：写入后 `localStorage` 里确实是新值

> 关于决议 007 §1 否掉的「别名」方案：我这里用的是**取值器**（`get(){ return SJ.Save.data.slots }`），
> 不是在 `create` 时抓一份数组引用。取值器每次都读**当前**的 `SJ.Save.data`，
> 所以 `Save.load()` 换掉整个 `data` 对象之后依然指向新的那份 —— 决议担心的静默断开不会发生。
> 已实测：`Save.save(); Save.load();` 之后 `SJ.player.slots === SJ.Save.data.slots` 仍为 `true`。
> `setSlot` 照样实现了，H 按决议调它即可。

### `SJ.Player.envForce(ax, ay)` — 环境加速度（G 调用，每帧累加）
**给 G 的标定：稳态漂移速度 ≈ `ax / 5`（px/s）。** 实测线性：

| `ax` | 漂移 |
|---|---|
| 300 | 47 px/s（轻微推搡，站着能感觉到） |
| 900 | 140 px/s（明显被吹，还能顶着走） |
| 1800 | 279 px/s（比走速还快，站不住） |

第四回的风建议从 **600–900** 起调。玩家逆风仍能行走（实测逆风 900 时向左净移动 93px）。

> **实现说明（重要，G 不用管但值得知道）**：环境速度存在独立的 `p.envVx/envVy` 里，
> **不并进 `p.vx`**。因为走路摩擦是 3200：任何小于 3200 的风都会被当帧抹平，
> 大于 3200 又直接失控 —— 那不是旋钮，是悬崖。分开积分后风才是线性可调的。
> `envForce` 的签名与「累加、physics 消费后清零」的语义完全按决议 009 实现；
> hitstop（dt=0）那几帧累加的风会被丢弃而不是攒着，解冻时不会把人弹飞。

### `p.inkDrainMul` — 被动墨耗倍率（G 每帧可设，默认 1）
乘在 **`spendSoft`** 上，也就是「观势 + 身法」这两笔软消耗（有地板的那些）。
招式消耗不受影响（招式本来就没有地板，再乘倍率会直接锁死玩家）。
实测 ×3 精确得到 3.00 倍耗墨，且**墨 ≤20 的地板依然生效**（×5 时在 20 处纹丝不动）。
第四回「墨在雪中消耗加快」用它。
