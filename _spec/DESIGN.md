# 《说剑》 — 设计总纲

> 横版动作过关 · 水墨武侠 · HTML5 Canvas · 纯程序化美术与音频
> 目标游玩时长：单周目 30–45 分钟（8 章）

---

## 0. 铁律

1. **不出现任何外部素材**：没有图片、没有音频文件、没有字体文件、没有 npm 包、没有 CDN。所有画面用 Canvas 2D 笔触绘制，所有声音用 Web Audio 合成。
2. **优雅好看优先于实现复杂度**。宁可少一个功能，不可丑。每个视觉决定都要落到具体数字（色值、笔宽、透明度、缓动曲线）。
3. **不做教程弹窗**。玩法必须由关卡与敌人行为「教」出来，玩家自己发现。唯一允许的提示：场景中的墨字（像题壁诗一样写在墙上/地上），以及说书人的旁白暗示。
4. **纯 classic script**，无 ES module，无 build。全局命名空间 `window.SJ`。加载顺序由 `index.html` 决定（Lead 维护）。
5. 目标：Mac 上 Chrome / Safari / Dia 打开即玩，稳定 60fps。

---

## 1. 视觉基调

宣纸 + 焦墨 + 朱砂。整个世界是一幅正在被画出来的长卷。

```
纸底   #efe7d8   （带 3% 噪点纹理 + 四角淡淡的做旧晕染）
纸暗   #e2d7c1
焦墨   #1b1a17
浓墨   #35322c
淡墨   #6f6a60
飞白   rgba(27,26,23,0.12)
朱砂   #b03a2b   （只用于：血、致命预警、印章、主角的一根束发带）
石青   #4a6f7c   （只用于：水、雪、寒）
藤黄   #c8a55b   （只用于：灯火、领悟瞬间）
```

规则：
- 画面 90% 是纸色与墨色。彩色是奢侈品，一屏最多一处。
- 远景山峦用**极淡的墨**（alpha 0.10–0.18）大笔触，越远越淡越模糊；近景前景用**焦墨剪影**（alpha 0.85）并轻微失焦。
- 所有线条必须是**有粗细变化的毛笔线**（起笔重—行笔细—收笔飞白），绝不能出现等宽的 `lineTo` 直线。
- 角色是墨笔速写，不是像素图：8–12 段带粗细的笔画构成，靠关节角度做动画。
- 打击瞬间：一道朱砂/焦墨的**挥毫弧线**扫过，加 3–6 滴墨点飞溅（有重力、落地晕开）。
- 屏幕比例 960×540 逻辑分辨率，按窗口等比放大（`imageSmoothing` 开），devicePixelRatio 适配。

## 3. 核心机制（对玩家保密，靠关卡教）

### 3.1 墨（唯一资源）
- 主角没有蓝条，只有 **墨**（0–100）。身法、招式、观势全部耗墨。
- 命中敌人回墨（普攻 +6，招式命中 +4/段，完美观势 +18）。
- 墨越低，**整个世界越褪色**：全屏 alpha 与饱和度随墨线性下降；墨为 0 时画面接近一张白纸，敌人只剩轮廓，主角攻击力 -40%，且每秒掉 1 血。
- 这是全游戏的压力来源：**逼你进攻**。恢复只能靠打中人。
- 墨的 HUD 不是条，是画面本身（另有一枚淡淡的墨滴在左上角作为读数）。

### 3.2 观势 → 悟（学招）
- 每个敌人／Boss 都有 1–2 个**招牌招式**。出招前有 0.35–0.8s 的**起手式**（telegraph）：身形定住、一道**朱砂虚线**在空中预画出这一招的轨迹。
- 玩家长按 K 进入**观势**：时间放慢到 0.35×，画面墨色变淡，敌人的招式轨迹变得清晰完整（不观势时只看到断续的虚线）。观势每秒耗墨 12。
- 在敌招判定命中的那一帧仍处于观势中 → **完美观势**：格开（不掉血）、大幅回墨、敌人硬直 0.9s，并在主角身上留下一道**残墨**（该招进度 +34%）。
- 观势失败被打中 → 掉血，但残墨 +12%（挨打也在学）。
- 残墨满 100% → **悟**：全屏定格 0.6s，藤黄一闪，招式名以竖排毛笔字写出，加入招式槽。
- 招式槽只有 4 格，学会的招超过 4 个要在暂停菜单里换。**换招是玩法的一部分**（某些 Boss 只能被特定的招破）。

### 3.3 生杀
- 每个 Boss 战结束时对方倒地未死，画面给出无字的两个选择（一个朱砂的「剑落下」提示 / 走开）。3 秒不动 = 留手。
- 记录 `mercy[bossId]`。它改变：后续关卡里出现的杂兵种类、说书人的旁白、结局。
- **说书人会撒谎**：从第四回起，旁白讲述的事实开始与玩家的实际选择矛盾（你留了手，他说你杀了）。这是叙事核心，不要提示玩家，只让矛盾自然发生。

### 3.4 集大成
- 全部 12 招都学会 → 解锁隐藏结局。招式全部来自具体的人，结局界面按学会顺序列出「你身上有谁的影子」。

## 4. 章节结构（目标 30–45 分钟）

| 回 | 标题 | 场景 | 时长 | 内容要点 |
|---|---|---|---|---|
| 楔子 | 醒木 | 茶馆（雨天，灯火） | 2 min | 无战斗。控制一个听客走动、坐下听书。教走/跳/互动。结尾说书人一拍醒木，画面「翻页」入正文 |
| 一 | 竹林听雨 | 夜竹林，雨 | 4 min | 教普攻、跳、身法。刀客出现，第一次起手式。Boss：**雨中刀**（学：横云断） |
| 二 | 断桥客栈 | 三层客栈，雨夜，灯笼 | 5 min | 垂直空间、单向平台、多敌混战。Boss：**铁笛先生**（远程音波，学：裂帛） |
| 三 | 长河渡 | 河上竹筏、风、桥桩 | 5 min | 平台跳跃为主，弓手压制，浮筏移动平台。Boss：**渡口老翁**（长篙横扫，学：撑天） |
| 四 | 雪照山门 | 雪山石阶，风雪，视野受限 | 5 min | 环境：风雪推人 + 墨在雪中消耗加快。Boss：**白衣**（快剑，会分身，学：孤影） |
| 五 | 藏经阁 | 木楼书架、烛火、纸 | 5 min | 战斗少、解谜与压迫多；火会烧纸（地形随时间消失）。Boss：**守阁人**（只格挡不还手，必须用特定招破，学：无锋） |
| 六 | 城楼夜 | 城墙、旗、月 | 6 min | 全游戏敌人大杂烩。终战：**师兄**（会现学玩家用过的招，第三阶段用玩家的招打玩家） |
| 终回 | 说剑 | 回到茶馆 | 3 min | 揭晓说书人身份，按 mercy 数 + 学招数三分支结局 |

## 5. 剧情骨架（文本由叙事 agent 扩写，此处为骨架，不可改结构）

主角「无名」，一个不会武功的人。楔子里他是茶馆听书的客人；故事里他背着一柄没开刃的剑走江湖。

- 每一回开头：**茶馆的说书人**（黑底纸色竖排字 + 醒木声）讲一段，然后画面翻页进入该回。
- 每一回结尾：说书人给一句评断。这句评断从第四回起**开始与玩家的实际行为不符**。
- 第五回藏经阁揭示：所有人的招式都出自同一本书《说剑》——一本教人怎么讲一个好故事的书，不是武功秘籍。人们照着书里的故事去练，练成了武功。
- 第六回终战「师兄」：他说，只有把这个故事讲完（把主角杀了），书才成立。
- 终回揭晓：说书人 = 主角自己，多年之后，在茶馆里把这段讲给别人听；他讲的版本一直在改，因为**故事比事实更需要一个结局**。
  - **杀尽结局（mercy=0）**：故事讲得极好，茶馆坐满了人，下一个来杀他的人正坐在台下。
  - **留手结局（mercy≥4）**：故事没人爱听，茶馆空了，他放下醒木，走出去，成了楔子里那个听客——回环。
  - **集大成结局（学满 12 招）**：他把书烧了。字散成墨，落回纸上；最后一屏是一张空白的宣纸，一枚朱砂印。
  - 混合（mercy 1–3）：折中结局，说书人念一段自己也不确定的评断。

## 9. 修订条款（优先级高于以上全部内容）

### 9.1 无锋的学习路径
守阁人**不出招**，所以他的「起手式」就是他的**守势**本身：他每次架起格挡时登记一个 `telegraph`（`moveId:'wufeng'`, dur 1.2s, danger:false）。玩家在他架防期间观势 → 读到 34%。这是全游戏唯一一个「观势一个防御动作」的设计，第五回要靠关卡（墙上的墨字、他一动不动的姿态）把这层意思透出来。

### 9.2 非战斗学招
`SJ.Tech.gain(moveId, amount)` 必须能被关卡 trigger 直接调用。
- `tiyun`（踏云）：第四回雪山，踩到某处风口被吹起时触发 trigger，`gain('tiyun',100)`。
- `fenshu`（焚书）：第五回藏经阁，第一次让火烧到自己身上时触发，`gain('fenshu',100)`。
两处都不给文字说明，只有画面演出（藤黄一闪 + 竖排招名）。

### 9.3 墨的保底（防止软锁，必须实现）
1. **主动消耗有地板**：身法与观势在墨 ≤ 20 时**不再扣墨**（依然可用）。招式没有地板，墨不够就是放不出来。
2. **枯墨不致死**：墨=0 时每秒掉 1 血，但**最低掉到 1 点血为止**，永远不会因枯墨而死。
3. **场景回墨**：可击碎的场景物件（灯笼、酒坛、竹节、经卷、雪堆）被打碎回墨 10–15。第三回与第五回必须沿路铺够（每 600px 至少一个）。
4. **砚**：第三、五回各放 2–3 个「石砚」存档点式的回墨点，接触即回满墨（一次性，重生后复位）。

### 9.4 新增操作
| 动作 | 键 | 说明 |
|---|---|---|
| 互动 | W/↑ 或 F | 只在 trigger 区域内有效（坐下、推门、看墙上的字、拾取） |

### 9.5 归属补齐
- 生杀抉择的**演出与 UI** 由 H 实现：`SJ.Story.mercyChoice(bossId, cb)`；G 在 `SJ.Level.bossDefeated` 里调用它。
- **墨褪色滤镜**由 G 在 `SJ.Level.draw` 末尾统一应用：读 `SJ.Player.inkTint()`，用一层 `SJ.C.paper` 的 `globalAlpha = (1-tint)*0.72` 覆盖全屏（外加轻微降对比），HUD 与对话层**不受影响**。

### 9.6 时长预算（硬性）
`SJ.Levels` 每关必须写 `expectedSec` 与 `encounters`（遭遇战数量），并在注释里说明预算依据。
**全部 expectedSec 之和 ≥ 1800（不含死亡重试）**。
横向移动只值 15–25 秒/关，时间必须来自遭遇密度、Boss 血量/阶段、剧情段落。
通关结算画面显示 `SJ.Save.data.playtimeSec`。
