### 1.2 笔墨库补强（`ink.js` / `fx.js`）—— 全部「加参数、缺省不变」

| 加了什么 | 说明 |
|---|---|
| `Ink.bamboo(o.poisson)` | 0..1。低频噪声给出疏密，逐格独立判定（层缓存按下标窗口重绘，不能依赖前一格） |
| `Ink.water(o.reflect / reflectFrom / reflectScale / reflectAlpha / strips)` | `reflect` 是「把水面上方那些东西再画一遍」的回调，本函数负责镜像 + 切条错位。**`reflectScale` 是关键**：横版的水面只有几十像素高，等比镜像的山影全落在屏幕外，压到 0.18 才落得进水里 |
| `Ink.water(o.shore)` | 沿水面顶边一道不规则岸线（值即 alpha） |
| `Ink.water(o.n)` | 原来 `o.n \|\| 7` 让 `n:0` 静默变成 7；改成 `!= null` 判定，`n:0` 才真的能只要倒影不要波纹 |
| `Ink.splat(o.aniso / o.dir)` | 去对称。缺省 `aniso=0` = 原样；传了才把卫星墨点收拢到 dir 一侧、细丝画成带弧的一甩（均匀分布 + 直细丝正是「蜘蛛腿」的来源） |
| `FX.leaf` 的 `spin/vspin` | 翻面。绕长轴转过去时横向被压扁，转到侧面几乎只剩一条线；竹叶的笔宽与叶腹鼓度一起收，有了正反两面 |

**⚠ 一个要 Lead 裁的取舍**：「`Ink.splat` 去对称」做成了 **opt-in**，所以**游戏里当前零处生效**。
理由是同一条任务里写着「加参数、不改缺省行为（旧调用点画面不变）」—— 去对称如果做成缺省，
就等于改了所有旧调用点的画面，两条要求直接打架，我选了守「缺省不变」。
仓库里唯一能传 `aniso` 的非 dev 调用点是 `story.js:441` 的生杀演出，我没在那儿开
（那一屏的朱砂已经很满，再加定向飞溅会更满）。要真看到效果有两条路，**都需要你点头**：
① 我在生杀演出上开（我的文件，随时可做）；② T2 在 `combat.js` 的命中墨溅上传 `{aniso:0.7, dir:命中方向}`（他的文件）。

### 1.3 天气调色（都在 scenery.js 里做，没碰 `Ink.paper`，没碰 level.js 的 rain/snow/fog）

- **c4 雾**：整屏一层 0.06 石青（纸色偏冷）+ 远近两道山脊的天空渐变（sky 0.170 / 0.085，两层是**叠加**的）。
- **c5 火**：径向暖光低频闪（`0.74 + sin(1.3t)*0.20 + sin(3.7t+1.1)*0.09 + noise(0.9t)*0.07`），顶上一道被熏黑的洗。
- **c6 月与旗**：旗按 `def.env.windAx` 的符号定方向；c6 的 `env` 是空的（levels.js:798），**缺省往左**，与 `Ink.rain/snow` 的缺省风向一致。我没有要求 T1 给 c6 加 windAx —— 在 c4 那是真实的玩法力，不该为了让旗飘起来去动它。

**飞灰/雨/雪一律是 `t` 与 `hash` 算出来的确定性场，不进 FX 粒子池。**
理由：`Scenery.draw` 在暂停与 hitstop（dt=0）时照样每帧在跑，而 `FX.update` 不跑 —— 往池子里塞东西会一路堆到 `MAX=600`。

## 2. 验证链路（怎么量的）

用户主力浏览器是 Dia，Claude-in-Chrome 截图在这台机器上常失败。所以不走浏览器自动化，改成：

```
dev/qa.sh → dev/qa_server.py（静态服务 + POST 落盘，带 no-store 头）
          → headless Chrome 打开 dev/shot.html
          → 页面里逐屏 SJ.Game._render → getImageData 统计 → toDataURL → POST 回来落盘
```

`dev/shot.html` **手动接管 Game**（不调 `Game.init`，那会起 rAF 主循环，帧就不可控），
`Level.load(idx, true)` 跳过开场，把玩家放到检查点、步进 6 帧落稳、收掉落地时踩到的旁白，再固定 `Game.time` 出帧。
一次跑完八关三机位 + 四张菜单 + 一张诊断。

**踩过的坑，写下来免得下一个人再踩**：
- Chrome 的 `--dump-dom` 跑完不退出 → 用 `perl -e 'alarm N; exec @ARGV'`（alarm 跨 exec 保留）兜底杀掉。
- 静态服务不发 `Cache-Control` 时，Chrome 会按启发式缓存**不回源**，你会对着上一版 js 调半天（我就中过一次：`getVolume is not a function`）。服务端必须发 `no-store`。
- 直接用真实游戏渲染路径出帧，而不是单画 Scenery —— DESIGN §1 说的「一屏」是**最终那一屏**，地形/deco/HUD/雾都要算进去。

### 2.1 纸色留白的口径（写死在这里，以后别换）

画面按 **4×4 取平均**后，`L = 0.299R+0.587G+0.114B ≥ 218` 的块算作留白。
纸底 L=231.6；四角做旧压到 ≈224（仍算）；任何 alpha ≥ 0.10 的墨罩 L ≤ 211（不算）。
先做 4×4 平均是为了抹掉纸纹噪点的 ±7，否则任何硬阈值都会在噪点上抖。
**这是偏严的口径**：人眼觉得「还是白纸」的极淡洗色，这里已经不算留白。

### 2.2 帧耗时的三个数

只报「清空全部缓存后那一帧」是不诚实的 —— 那一帧一局只出现一次。所以报三个：

- **静止帧均值**：24 次渲染取平均（层缓存命中，= 玩家站着不动时）。
- **走动中 p95**：镜头以 6px/帧（≈冲刺速度）推 110 帧，取 p95。这才是「某一层视差缓存到期重建」的真实代价。
  单次峰值也记了，但无头 Chrome 是软件渲染，偶发 GC 会让单帧飙到 8ms 以上 —— 那是环境噪声，不是画面成本，所以以 p95 为准。
- **载入帧**：`clearLayerCache()` 之后那一帧，= 换关卡时所有视差层同时重建。

## 3. 什么没验证（诚实清单）

1. **没有人眼看过动的画面。** 全部结论来自静止帧。会动的东西 —— 水波与倒影的错位、飞灰、旗、火光闪烁、竹叶翻面、音量条的呼吸点 —— 我只在单帧上看过。节奏对不对（火闪得是不是太快、旗飘得是不是太假）需要人看一眼。
2. **帧耗时是软件渲染（`--disable-gpu`）下的数字**，而且测的时候这台机器 load average 5–7（别的 teammate 在跑）。所以我报 p95 而不是峰值，并把每关重测过两遍取稳。真机（GPU 合成）只会更快，但**我没在真机上量过**。
3. **音频完全没听过。** 音量条只做了数值断言。50ms 斜坡到底有没有消掉「咔」声、0.1 的步进跨度是不是合适、按住连调的速度顺不顺手 —— 都没人试过。
4. **页码只截到了一屏**（c5_book 第四屏）。其它 ≥ 5 屏的链（例如楔子的 tea 长链**不标页码**，这是刻意的）没有逐条看过。
5. **c4 的雾下观感**只有静止帧。提灯人走动时雾洞扫过天空洗色是什么样，需要有敌人在场才看得到 —— 没验证。
6. **和 T2 / T3 的改动没合过。** 招式姿势、预警分层、boss 阶段演出落地后，跟新背景叠在一起是什么样，没试过。
7. **只在 headless Chrome + node 上跑过。** Safari、Dia、真实窗口缩放（DPR≠1）下没开过。`shot.html` 强制 scale=1，真机是按窗口等比放大的。
8. **`FX.leaf` 的翻面没在游戏里看过** —— 触发点在第五回的燃烧（纸屑）与第四回的雪堆，两处都得打到那儿。
9. **`Ink.splat` 的 `aniso` 在游戏里没有生效点**：仓库里唯一能传它的非 dev 调用点是 `story.js` 的生杀演出，我保守起见没在那儿开（那一屏的朱砂已经很满）。要看效果得 T2 在 combat 的命中墨溅上传。
10. **暂停界面纸色留白 0.0%** —— 见下。

## 4. 给别人文件的三条发现（我没动）

1. **`src/level/level.js:521`（T1）**：`SJ.Ink.wash(..., { dir: 'down' })`。
   `Ink.wash` 只认 `dir === 'v'`，其余一律当**横向**。所以所有 solids 的「体积渲染」现在是从左到右渐隐，
   不是设计要的「往下淡出」。改成 `dir:'v'` 即可。（`drawDeco` 里的 stele/shelf 没传 dir，是对的。）
2. **`src/level/level.js:804`（T1）**：`R.fog = (def.weather === 'snow') ? 1 : 0`，第四回**全程满雾**

## 6. 以后要动这一层的人，先看这几条

- **`Ink.mountains` / `Ink.bamboo` 的**每一个**参数都在层缓存 key 里**（`baseY`、`alpha`、`band`、`gap`、`seed`、`poisson`…）。
  传任何跟 `t` 或 `camY` 有关的值进去 = 每帧重建一张 1400×540 的离屏画布。
  要竖向视差就在外面 `g.translate(0, -camY*par)`，别动参数。
  同理：c3 的倒影**必须**用与正画时逐字相同的参数调 `farHills`，才能复用同一张缓存。
- **`level.js` 从来没调过 `Ink.clearLayerCache()`**（换关卡也没有）。目前靠 key 里的 seed/alpha 区分，不会串关，
  但缓存只增不减。真要清，得 T1 在 `Level.load` 里加一行。
- **c2 / c5 的室内构件没有走层缓存**（它们要跟着 camY 动，而 layerBlit 只处理横向）。所以是逐帧真画的，
  c5 最贵（0.42–0.55ms）。要再加东西前先量一次。
- **Scenery 里绝不要 spawn FX 粒子**（理由见 §1.3）。
- 一屏最多一处彩色：**scenery.js 里朱砂一次都没用**（留给主角发带与致命预警）。藤黄只给灯与火，石青只给水、雪、夜。
