## 0. 一句话

一个不会武功的人走了六处地方，杀了或没杀六个人；讲这个故事的说书人，就是他自己，
而他已经把这个故事改了二十年，改到自己也分不清哪一段是做的、哪一段是说的。

## 2. 全剧走向

| 段 | 说书人状态 | 剧情 |
|---|---|---|
| 楔子 | 套话齐全（「话说」「看官」「诸位」） | 听客进茶馆坐下听书。老客已埋下「一回一个样」 |
| 一–三回 | **叙述与玩家行为完全一致** | 竹林 / 客栈 / 长河。第三回收尾问一句「诸位听得可还对得上？」 |
| 四回 | **开始矛盾**。先自陈「记不太清了」 | 雪山。关卡中途 `c4_mid` 把**第一回**的结局说反；outro 把**本回**说反 |
| 五回 | **开始辩解**：「准头是听的人给的，不是事给的」 | 藏经阁。题眼＋`c5_t_page`：书里写着刚走过的第四回，且写错的方向与说书人一致 |
| 六回 | **转向听众质问**：「诸位在场么？」 | 城楼。师兄要一个结局 |
| 终回 | 承认改了二十年 | 揭晓说书人＝无名。三结局＋中间态 |

**叙事核心的三次矛盾**（全部不加任何提示）：
1. `c4_mid` — 关卡内，说反第一回；
2. `c4_outro` / `c5_outro` / `c6_outro` — 每回收尾说反本回；
3. `c5_t_page` — **书上的字**和说书人说的一样错。这是把「说书人」与「那本书」焊在一起的一屏，
   也是玩家第一次能拿到物证。它的错误方向与 `c4_outro` 严格同源（都读 `mercy.baiyi`）。

## 3. 节点格式与分支约定

### 3.1 字段
```js
key: { speaker, mode, lines, next, cond, seal }
```
- `speaker`：`'说书人'|'无名'|人名|''`（`''` ＝ 无署名，旁白与题壁）
- `mode`：`'tea'` 说书人段落 / `'talk'` 角色对白 / `'card'` 章节卡 / `'narration'` 场景旁白
- `lines`：已断好行的短句，**每行 ≤18 汉字**，一屏 **2–5 行**
  - 例外一：`speaker==='无名'` 允许**单行**（他的沉默是角色的一部分）
  - 例外二：`mode==='card'` 允许单行（结局最后一屏）
- `next`：下一个 key，`null` 结束。**每个节点都显式写 `next`**
- `cond`：`(save)=>bool`，缺省视为 true
- `seal`：**只有 `f_end_all_e` 有**。值 `'无名'`。H 需在该屏画朱砂印

### 3.2 分支＝链式跳过（chain-skip）

> **给 H 的实现要求**：`SJ.Story.play(key)` 在进入时与每次 advance 时都对当前节点求值
> `cond(SJ.Save.data)`；**false → 不显示该屏，直接跳到它的 `next`**；`next:null` 结束。

互斥变体线性串联，最后一个变体的 `next` 指向汇合点：

```
c4_outro      （无 cond，中性首屏）  next → c4_outro_a
c4_outro_a    cond: 留了白衣          next → c4_outro_b
c4_outro_b    cond: 杀了白衣          next → c4_outro_end
c4_outro_end  （无 cond）             next → null
```
留手：显示 a → 到 b，b 的 cond 假被跳过 → 落到 end。
杀　：a 的 cond 假被跳过 → 到 b，显示 b → 落到 end。两条路都正确。

**两条硬保证**（由 `dev/script-check.js` 强制）：
1. 所有会被 `play()` 的**入口 key 一律无 `cond`**（H 若只在 advance 时求值也不会出错）；
2. 每组变体互斥且穷尽；任何存档下链必定终止、无环、至少显示一屏。

### 3.3 `save.mercy` 方向 —— 唯一定义处

**`save.mercy[bossId]` 为真 ＝ 留手（没杀）**，依 DESIGN §5「留手结局 mercy≥4」。

⚠️ `SJ.Story.mercyChoice(bossId, cb)` 的回调是 `cb(true=杀)`，**G 写入时必须取反**：
```js
SJ.Save.data.mercy[id] = !killed;
```
写反的话，第四至第六回的矛盾旁白会全部倒过来变成「说的和做的一致」，
**不可靠叙述者这一叙事核心会静默失效，且没有任何测试能抓到**。
要改方向，只改 `script.js` 顶部的 `spared()`。

⚠️ **写入时机同样关键**：所有 `cN_outro` 的 `cond` 是在 `play()` 那一刻读 `SJ.Save.data.mercy`。
CONTRACTS 里 `Level.complete()` 是「播 outro → 存档」，outro **先于**存档发生。
所以 G 必须在 `mercyChoice` 的回调里**当场写进内存中的 `SJ.Save.data`**：

```js
SJ.Level.bossDefeated = function (id) {
  SJ.Story.mercyChoice(id, function (killed) {
    SJ.Save.data.mercy[id] = !killed;   // ← 立刻写内存，不要攒到章末再 flush
    SJ.Level.complete();                // complete() 里才播 cN_outro
  });
};
```
若 G 把选择暂存在关卡局部变量里、等到 `SJ.Save.save()` 时才落盘，
每一回的 outro 都会读到**上一回的旧值**，说书人就从「故意说反」变成「随机说错」——
与方向写反同一类的静默失效。

### 结局（入口 `f_end`，四支互斥穷尽，优先级自上而下）

| 支 | 条件 | 首 key | 收束 |
|---|---|---|---|
| **集大成** | `known.length >= 12` | `f_end_all` | 烧书 → 字散成墨 → **空白宣纸 ＋ 朱砂印「无名」＋「不说了。」**（`f_end_all_e`，带 `seal`，`mode:'card'`） |

`SJ.Menu.ending(kind)` 的 `kind` 建议取 `'all'|'kill'|'mercy'|'mid'`，判定逻辑与上表一致。

## 7. 自检

```bash
node dev/script-check.js
```

检查项：
1. `node --check` 级语法 ＋ 结构（mode 枚举、speaker 类型、`next` 显式存在、`cond` 是函数）
2. 每个 `next` 指向的 key 存在
3. 行长 ≤18；行数 2–5（`无名` 与 `card` 允许 1）
4. 玩法术语黑名单 grep
5. **入口 key 一律无 `cond`**
6. 孤儿节点告警
