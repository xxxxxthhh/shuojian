## 2. 每关的设计意图与教学点

### 楔子「醒木」105s · 0 遭遇
街上两块垫脚石教跳，门槛/茶博士/老客/孩子/空座五处互动教互动键。
`p_kelao` 是**走过就听见**，`p_kelao_b` 要**停下来按互动**——「一回一个样」这句伏笔，
路过的人只听见半句，肯站住的人才听见老客当场把说书人拆穿。这是全剧第一次分层给信息。
靠窗那张桌（deco `table x3180` + `seat x3230`）与终回的 `f_t_seat` 是同一张。

### 一「竹林听雨」245s · 4 波 + 雨中刀
**唯一一关不设坑**——玩家该死在人手上，不该死在地形上。
| 波 | 配置 | 教什么 |
|---|---|---|
| w1 | 刀客×1 | 看清一次起手式（`c1_t_watch` 就在前面 180px，`wall_c1_a`「未出鞘 先见招」再钉一遍）|
| w2 | 刀客×2 | 两条起手式重叠，逼你挑一个观 |
| w3 | 刀客×2 + 力士 | 力士直线冲撞，观势格不划算 → 身法穿过（`c1_t_dash` 紧贴）|
| w4 | 刀客×3 | 密度足以把墨打枯一次，逼你进攻回墨 |
`c1_t_ink`（墨会枯）刻意放在 **w1 打完之后**的 1360——先让墨真的掉下去，再说那句话。
`learn_ink` / `learn_hurt` 挂 `when:'firstInk'` / `'firstHurt'`，没有位置。

### 二「断桥客栈」300s · 5 波 + 铁笛先生
断桥（落水回检查点）→ 螺旋三层。
w2 的弓手站在 2350 的**挑台**上（离一层 120px，跳得上去）。这条很关键：
第二回还没有远程招，如果把弓手放在够不着的地方，「退无可退」就变成「无解」。
**答案是换位置，不是硬吃**——这是本作远程压制的第一课。
w3 的隘口是一层最右端的上楼梯口，力士带两个刀客只能排着下来。
w4 二层长廊两端交叉火力 + 两个立柜掩体。

### 三「长河渡」330s · 4 波 + 2 个游荡弓手 + 渡口老翁
**墨保底重点关**：18 个可击碎物件（最大间距 360px）+ 3 个石砚。
`c3_t_yan`（石砚那句「笔干了，来这里蘸一蘸」）挂 `afterWave:2`——
先让中洲一的两个弓手把墨耗干，再让玩家看见石砚。顺序反了这句话就白说。
2760 / 3680 两根桩上的**游荡弓手**（wave 0，不锁 gate）是本关唯一的战术自由度：
过筏时一直被射，你可以冲过去也可以先跳上桩把他做掉。

### 四「雪照山门」325s · 4 波 + 白衣
风向左推（`env.windAx = -150`）、雪中墨耗 ×1.6（`env.inkDrainMul`）。
2800–2960 是**断崖**，唯一的过法是站进风口被吹上去 → `SJ.Tech.gain('tiyun',100)`。
风口常开、崖底另铺一层实心地面，掉下去只会被重新托起，绝不出图也绝不卡死。
`wall_c4_a`「风起处 可借一步」就刻在风口前那块石头上。
`c4_mid`（说反第一回）挂 `afterWave:2` @2020——半山腰，画外音，**不切茶馆**（决议 003 §3）。

**提灯人＝雪山唯一的光源（决议 008 §5）。** 两个都是 `wave 0` 游荡兵，**刻意不放进任何带 gate 的波**：
带 gate 的波「清完才能往前」，把他放进去就等于**必须杀**，这一关最好的那层选择当场作废。
现在的关系是：杀了他视野就没了，留着他他就一直跟着你打——玩家自己去权衡。
#1 @2700 摆在**断崖/风口前那块台上**（光最值钱的地方：那一跳你想看得见），#2 @3450 在最后一段爬升。
**两处都有不带光也过得去的走法**，不做强制解。`c4_t_deng`「借个光？」跟着挪到 2580，第一次撞见他的位置。

### 五「藏经阁」335s · 3 波 + 守阁人
**墨保底重点关**：14 个经卷/烛台（最大间距 400px）+ 3 个石砚。只有 3 场遭遇，铺不够会枯死。
`fenshu` 走 `when:'burn'`（第一次被火燎到），不绑死在某一处火上。

**顺序按 STORY §4.2（D 裁定，驳回我原来的「先物证后题眼」，我接受）：**
`c5_t_shelf`(560,一层) → w1 → 火起 → 上二层 → **`c5_book`(1990, 二层主路径, 9 屏)**
→ 上三层 → w2 + `c5_t_burn` 火势 → 上顶层 → **`c5_t_page`(3530, 顶层最深处, 4 屏)** → w3 → Boss。
Δx = 1540px，中间夹着 w2 一整场遭遇与火势推进（决议 004 §2 满足，检查器方向无关）。
D 的三条理由成立：① 反过来会把 `c5_book_d`「这本书写的是我」从揭示降级成复述；
② 物证「纸是旧的，至少有二十年了」与终回「讲了二十年」同源，是**落点**不是引子；
③ 它直接喂给守阁人第一句「还手的，都写进去了」——三拍是一条链。
而且这个顺序把 9 屏放在**离 Boss 最远处**，比我原来的更不容易堆成一堵墙。

**★ STORY §4.2.1：`c5_t_page` 不得可错过——我原来的摆法是错的。**
我把它放在三层侧龛、要跳上去、`interact` 才读，即**可以整关不触发**：
错过它的玩家会完整通关，且永远不知道自己少了全剧唯一一处硬证据。
现在的解法保留了 `interact`（「自己翻开的」这个动作是这一屏的全部力量），
但把那一架**倒下来横在路上**（新增 `blockers` 字段），不翻开就过不去。
**翻开＝挪开＝读到，三件事是同一个动作**——玩家仍然是自己翻的，只是躲不掉。
检查器规则 13 会验证 blocker 的 flag 确实由一个位于它之前的 trigger 设上（否则是死锁）。

**★ 会烧掉的木板一律不放在主路径上**（这是我改过的一个真 bug 的教训）：
2300 / 3450 两块 `flag=2` 是**侧龛**，只承载拾取物；烧掉损失的是墨，不是通路。
主路径（二层 1780–2850、三层 2980–3900）全程连续，一层是整层通铺的实心地面，
从任何地方掉下去都只是掉一层，走回楼梯再上来——永远不会软锁。

### 六「城楼夜」410s · 5 波 + 师兄
全游戏最长。11 拍旁白按 STORY §4.1 摆，详见 §4。

### 终回「说剑」150s · 0 遭遇
与楔子刻意同构：同一条街、同一道门槛、同一张靠窗的桌。
区别是这一次玩家是**从台前走过去**的，不是从门口走进来的。
`outro: 'f_end'`——`SJ.Story.ending()` 也只是 `play('f_end')`，分支全在 script.js 内部。

## 3. 契约之外我加的字段（纯追加，没改任何已有语义）

| 字段 | 为什么 |
|---|---|
| `trigger.event` 是**对象**不是字符串 | `{play, gain, flag, fireStart, music}`，声明式 → `dev/level-check.js` 不执行任何代码就能校验 script key 与招式 id |
| `trigger.when` 字符串枚举 | `wave:N` / `afterWave:N` / `firstInk` / `firstHurt` / `burn`。决议 004 §1 的「波中/波后」是硬约束，必须能被机器读 |
| `trigger.interact` | DESIGN §9.4 的互动键；题壁与书架都要玩家自己按 |
| `bossScript{pre,mid,down,p2,p3}` | 契约的 `boss:null\|id` 装不下五个剧本 key；写死在 level.js 里检查器就看不见了 |
| `bossArena` / `bossY` / `bossMusic` | 战斗区间、Boss 站的那层地面 y、boss/final 曲目 |
| `blockers[{x,w,flag,note}]` | 挡路物：flag 为真前玩家过不去。用来让 `c5_t_page` 保留 `interact` 又不可错过（STORY §4.2.1）|
| `solids[5] = burnAt` | `flag=2` 说了会消失，没说什么时候消失 |
| `waves[i] = {id,x,w,gate,sec,note}` | `gate` 是清完前把玩家夹住的 x 区间；`sec` 是预算里给这一波的秒数 |
| `env{windAx, inkDrainMul}` | 第四回专用，见 §7 待裁定 |
| `budget{walk,waves,boss,story,other,note}` | DESIGN §9.6 要求「注释里写清预算依据」，做成结构化的好让检查器验自洽 |

## 6. `dev/level-check.js` 查什么（12 类，全部做过变异测试）

1 schema / 枚举 / 宽度 3500–6000 / 检查点 2–4　　2 script key 存在且是**入口**（无 cond）
3 Σ expectedSec ≥1800 + budget 自洽 + encounters 自洽　　4 第三/五回回墨间距 ≤600 + 石砚 2–3
5 决议 004 §2（Δx ≥600 + 中间有遭遇 + `interact:true`）　　6 决议 004 §1（11 拍齐 / x 单调 / 教学拍紧贴其波 / `c6_t_wave2` 挂最密的波）
7 **地图没有洞**（每 20px 一列，下方必须有不消失的 solid 或 hazard）
8 spawn / checkpoint / pickup 脚下真的有地面，且没埋在实心块里；检查点不在 hazard 里
9 positional trigger 必须与某块地面的「玩家站立盒」相交（否则永远触发不了）
10 gate 包含触发点与全部 spawn　　11 `flag=2` 必须有 `burnAt` 且下方有兜底地面
12 **gate 软锁守卫**：被锁住的战场，玩家从 gate 内最低层必须爬得回战斗层
　（高差 ≤190 = 满跳 114 + 二段跳 ≈85；水平 ≤150 = 满跳滞空 144）
13 `blocker` 的 flag 必须由一个**位于它之前**的 trigger 设上（否则玩家永远过不去）
14 **全关通路可达性**：从起点做全图表面 BFS，所有检查点 / 波次触发点与 spawn /
　位置型 trigger / Boss 场地 / `exitX` 都必须走得到。浮筏算路，风口（updraft）算连接器。
　Boss 可达性按 `(bossArena[0], bossY)` 判 —— 只看 x 会把「站在 Boss 楼下的一层」误判成可达
15 **STORY §4.2.1 指名断言：`c5_book` / `c5_t_page` 不得可错过。**
　13/14 是通用规则，证明得了「走得通」，**证明不了「玩家一定会看到」**。这条按 key 指名，
　用两个真能证明「必经」的性质：
　**A 割点**——把承载这一屏的那块地面从可达图里删掉，Boss 就走不到了 ⇒ 绕不过去；
　**B 同层拦路**——`interact` 可以走过去不按，所以还要求它与 Boss 之间有一道 blocker，
　且该 blocker 的 flag **只**由这一屏设、并与它**踩在同一块地面上**
　（同一块＝不是「跳上侧龛去读」，是「走到跟前非读不可」）。
　四个变异全部会炸，含 lead 点名的那个失败模式（把 `c5_t_page` 放回三层侧龛）

变异测试逐条验证过这 12 条**真的会炸**（不是空跑）。它在写的过程中抓出了 4 个真 bug：
- 第一回一个刀客被埋在岩石里；
- 第二回 / 第五回各有一个 spawn 在 gate 之外，玩家根本打不到；
- 第五回 `c5_t_burn` 挂在一块会烧掉的木板上（板一没，这一拍永远播不出来）；
- 第二回原来的「一层→二层楼梯在中段」布局会造成**软锁**：gate 锁住二层长廊，玩家从单向
  平台掉到一层就再也上不去。第二回因此整关改成了螺旋动线（楼梯在每层的端点），
  每个 gate 都把该层的楼梯包在里面。
- **第五回原来整条主线是走不通的**：三层 2700→3000 有 300px 断口、2700 那段二层到三层
  差 220px 又没有梯子，即 w2 / 火势 / 顶层 / Boss **全部不可达**——而数据看着完全正常。
  规则 12 只管 gate 之内，管不到「整关根本走不通」，所以补了规则 14（全图 BFS）。
  这条是这份检查器里最值钱的一条：它抓的是**看不出来**的那类错。

## 7. 我觉得最脆的地方（按严重度排）

1. **Boss 时长是假设，不是数据**（见 §5）。490 秒里我一秒都没实测过。
2. **第五回可能不好玩。** 这是我最担心的一关：3 场遭遇、33 屏文本、火在烧地板。
   如果 H 的对话推进手感稍慢，`c5_book` 那 9 屏会变成一堵墙。我做的对冲是
   「题眼之后还有一场遭遇才到 Boss」，但真正的解法在 H 那边（翻页要快、可跳字）。
   守阁人只能用无锋破，如果玩家没在他架防时观势够，会卡在那儿磨很久——
   这一关的失败模式是**卡住**，不是**太短**。
3. **第四回可能不好受。** 逆风 −150 + 墨耗 ×1.6 + 视野受限，三个负面 buff 叠在一关。
   数字是我按「能感觉到但不至于难受」拍的，没有实机验证过。
   `env.windAx` / `env.inkDrainMul` 都是数据，实机觉得烦就直接调小。
4. **第三回的浮筏是唯一一个需要 level.js 做特殊物理的东西。**
   `World.moveX` 不会把筏的位移带给站在上面的玩家，得 level.js 自己加。
   我把关卡设计成「掉筏 = 落水 hazard → 回检查点」，永远不会摔出图，
   但如果带载做得不对，站在筏上会一直往后滑，手感会很差。
5. **第四回整座山是实心块，画出来可能是一大坨墨**，违反 DESIGN §1「一屏纸色空白 ≥50%」。
   这是**阶段二的渲染问题**：山体内部要用飞白与淡墨渲染，不能填死。写 `Level.draw` 时留意。
6. **gate 的手感未知。** 「清完这波才能往前」是不是让人烦，只有实机知道。
   所有 gate 都是数据里的一个字段，改成 `null` 就退化成不锁。

## 8. 阶段二（`src/level/level.js`）开工前记下的约束

- **`SJ.Level.bossDefeated(id)` 必须调 `SJ.Story.mercyChoice(id, cb)`，绝不自己写 `SJ.Save.data.mercy`**（决议 002 §2）。
- 时序（决议 003）：Boss 倒地 → `play(bossScript.down)` → `mercyChoice` → 回调里演出
  → `Level.complete()` → 播 outro → 存档。**不许把 mercy 攒到章末 flush。**
- 每帧调用顺序照抄决议 005 §3，一行都不能漏。
- `Level.draw` 末尾统一应用墨褪色：读 `SJ.Player.inkTint()`，覆盖 `SJ.C.paper`，
  `globalAlpha = (1-tint)*0.72`；**HUD 与对话层在褪色之后画**。
- 有 Boss 的关卡：**通关由 `bossDefeated` 触发，不是 `exitX`**。`exitX` 只用于楔子与终回，
  以及有 Boss 关的「走出去」标记。
- `SJ.Level.pickups` 由 `deco` 里带 `ink` / `refill` 的项生成；石砚一次性，**重生后复位**。
- **决议 009 §1（已裁定）**：环境力**只能**走 E 的接口，`SJ.Player.envForce(ax, ay)`（本帧外部加速度，
  physics 消费后自动清零）与 `p.inkDrainMul`（默认 1，G 每帧可设）。
  **不许直接加 `p.vx` 或直接扣墨**——会和玩家自己的加速度/摩擦抢同一个字段，
  表现是「风时有时无」且无法复现。第四回每帧设 `envForce(env.windAx, 0)` 与 `inkDrainMul = env.inkDrainMul`。
- **决议 006（已裁定）**：`playtimeSec` 由 `SJ.Game` 单独累加（用 `rawDt`，唯一写入者），
  **G 不要再加**。A 已实现。
- **决议 005 §3：每帧调用顺序照抄，一行不能漏。** 漏掉任何一行都不报错，只会让某个系统静默消失。
  最危险的是 `SJ.Combat.draw(g)`——它画的是敌人起手式的朱砂轨迹，
  而那是「观势」**唯一的视觉教学手段**（DESIGN §0 铁律 3 不许做教程弹窗）。这条线一断，
  玩家永远不会发现该按住那个键，整个学招系统变成死代码，而游戏照样跑、不崩、不报错。
  三个容易排错的点：`Tech.update` 必须在 `Combat.update` **之前**（招式也产生 hitbox，产生者先于统一结算）；
  `Combat.draw` 必须在 `Camera.apply/restore` **之内**（世界坐标）；
  `HUD.draw` 必须在墨褪色覆盖层**之后**（褪色只作用于世界）。
- **决议 008 §5：雪山的雾/视野受限归我。** 读 `SJ.Ent.by('foe')` 上的 `e.light = {r, warm}`
  在雾层上开洞；敌人自己画 `SJ.Ink.lantern`，我不画灯。
  **雾层要画在墨褪色覆盖层之前**——雾是世界的一部分，褪色作用于整个世界。
  即决议 005 §3 的第 7 步与第 8 步之间。
