## 3. Boss 招式表

每个 Boss 都 `superArmor: true`：**普通命中不产生硬直**。
能打断他们的只有两件事：完美观势的 0.9s，以及阶段转换。
（不这样的话，玩家的三连普攻 stun 0.18/0.24/0.30 且后摇可取消，
任何 Boss 都会被永久锁死在起手式里。）

### 五回 · 守阁人 `shouge` — hp 320，3 阶段（68% / 34%）
> 「我不还手。还手的，都写进去了。」

**他的伤害是 0。全部。** 这场仗玩家不会死（枯墨也保底 1 血），
压力来自墨与时间，不来自血。DESIGN §4 说第五回「战斗少、压迫多」，我按字面做了。

| 阶段 | 招 | 起手 | 说明 |
|---|---|---|---|
| P1–P3 | **守** | **1.20** (`danger:false`, `moveId:'wufeng'`) | 决议 9.1。观势读满一半 → 无锋 +34% |
| P1–P3 | 退步 | 0.40 (`danger:false`) | 拉开距离 |
| P2·P3 | 震脚 | 0.66 | **伤害 0**，但击退 420、打断观势、**抽走 10 点墨** |
| P3 | 合十 | 0.90 (`danger:false`) | 你 6 秒没伤到他 → 回 24 血 |

**破他的唯一办法**：`opt.moveId === 'wufeng'`。
他**无视 `guardBreak`** —— 普攻第三段在僧人身上管用，在他身上不管用。
（tech.js 里 E 给无锋的 hitbox 是 `dmg:0, moveId:'wufeng', guardBreak:true`，接口对得上。）
撬开后 `openT = 2.6s`，这段时间他手垂着，正常吃伤害。

**实测学会无锋要多久**：站着一直观势 → **2.8s / 13.0s / 22.6s** 各 +34% → **22.6s 学会**，
学会后自动进第一个空槽。墨在 20 触底不再扣（DESIGN §9.3），全程掉到 20 就不再掉，
所以不会被卡死。

**读不出无锋会怎样 —— 决议 008 §3 的「线索升级」**：
僵持不是死局，但也不能是无限僵局（玩家卡在这里退出游戏比被打死严重）。
所以他会**把线索变清楚，而不是把伤害变高**：

| 僵持时长（游戏内时间） | 守势起手式 | 其它 |
|---|---|---|
| < 40s | 1.20s | 常态 |
| 40–70s | **1.70s** | 守势冷却缩到 0.35s，线索来得更密 |
| > 70s | **2.21s** | 身上浮起一层呼吸的**藤黄**（本作里「领悟」的颜色） |

实测 90 秒不观势：`1.2s ×12 → 1.7s ×8 → 2.21s ×5`，逐级升上去。
**计时用 `SJ.Game.time`，不能在 think 里累加** —— 他绝大部分时间都待在「守势」这个招里，
think 根本不跑，累加出来的只有真实时长的三成（第一版就是这么写错的，实测才发现）。
用游戏内时间还有一个好处：**观势期间时间走 0.35×，所以正在观势的玩家不会被催** ——
他做的正是对的事，二十来秒就读满了。

我没有用朱砂：朱砂在本作里的意思是「这一下会打你」，给守势染朱砂是**撒谎**。
藤黄是「领悟」的颜色，把眼睛引过去而不改变语义。

## 4. 公平性实测（这是我最想让 Lead 看的一节）

`dev/enemy.html` 里有一个**反应机器人**：起手式出现后延迟 L 秒按住观势，
统计每一招的格开／挨打。飞来的箭与音波也按同样的延迟计时（人是看着箭飞过来的）。
用 `SJ.Game._step()` 手动推帧，所以结果是确定性的，跟帧率无关。

> **必须先说清楚的一件事**：浏览器自动化的**键鼠事件送不进页面**
> （Dia 的窗口不在前台，`requestAnimationFrame` 被节流到几乎不动，点击也不触发）。
> 所以下面所有数字来自 `SJ.Game._step()` 确定性推帧 + 合成 `KeyboardEvent`，
> **截图是真实渲染出来的画面**，但**没有一次是人手真的打的**。
> 我认为机器人统计在「窗口公不公平」这件事上比人工试打更可信（几百次采样、确定性、可复现），
> 但它测不到手感 —— 打起来爽不爽、起手式看着累不累，**还需要一个人真的坐下来打一遍**。

### 结论一：反应预算 = 起手式时长，不多不少

机器人是一个纯阈值检测器，所以结果非常干净：
**起手式 > 延迟 + 0.02s → 100% 格开；否则 0%。** 没有隐藏的宽限，也没有隐藏的亏空。
系统是诚实的 —— 这也意味着 **0.35s 的下限就真的只有 0.35s**。

> ⚠ **这张表的前提是玩家站着不动、不攻击。** 玩家一旦在挥剑，观势进不去，
> 结论完全不同 —— 见下面的结论二与结论三。**看这一节请连着看完三条。**

| L=0.35s 的机器人 | windMul 1.0 | 0.80 | 0.62 |
|---|---|---|---|
| 刀客 破雨 (0.70) | 14/14 | 15/15 | 20/20 |
| 刀客 横斩 (0.58) | 3/3 | 4/4 | **0/2** |
| 枪兵 直刺 (0.55) | 12/12 | 11/11 | **0/12** |
| 枪兵 镇山 (0.80) | 6/6 | 8/8 | 6/6 |
| 力士 连环腿 (0.65) | 12/12 | 13/13 | 15/15 |
| 刺客 闪 (0.52) | 10/10 | 3/9 | **0/7** |
| 提灯人 灯火 (0.60) | 13/13 | 15/15 | **0/2** |

**→ `windMul` 不要低于 0.75。** 0.62 会把一半的杂兵招压到反应窗口以下。

### 结论二：真正的公平开关不是起手式长度，是「玩家有没有被自己锁住」

`player.js` 里观势会被普攻 / 招式 / 身法 / 受击打断。
所以**在玩家挥剑到一半时起手的快招是不可格挡的**，起手式画得再清楚也没用。

`AI.pick` 里有一道闸：

```
起手式时长 − 玩家剩余锁定时间 ≥ 0.22s，否则这一招不许起手
```

`AI.playerLock()` 给出剩余锁定（普攻 0.26 / 第三段 0.36 / 招式 0.34 / 身法 dashT）。

我先试过一刀切「玩家 busy 时禁止 <0.70s 的招」，
结果**白衣 50 秒里只出了 5 招**，人物性格直接没了。按剩余时间算才既公平又不温吞
（同样条件下白衣 60 秒出 21 招）。

### 结论三：带真人节奏的玩家模型下的格开率

玩家模型：贴身时打一轮连段（0.4s）停 0.9s；**看见朱砂虚线立刻停手**；机器人延迟 0.32s。

| | 格开/总数 | 分招 |
|---|---|---|
| 雨中刀 P2 | **20/22 (91%)** | 横云断 10/10，雨落 4/5，破雨 4/4 |
| 铁笛 P2 | 11/11 | 三音 5/5 |
| 老翁 P1 / P2 | 24/24 / 16/16 | 旋风扫 3/3 |
| 白衣 P3 | **32/41 (78%)** | 遍照 4/5，孤影 5/6，快剑 23/30 |
| 师兄 P3 | **16/25 (64%)** | 横云断 6/8，镇山 4/6，孤影 3/3，快剑 2/5 |
| 四人混战（弓+枪+刀+力） | 31/31 | 同时起手的危险招**峰值 2**（`AI.maxAttackers`） |

难度曲线是我想要的形状：一回 100% → 四回 78% → 六回 64%。

### 结论四：稳定性

11000 步（**183 秒**）连续压力测试，每 15 秒换一个 Boss + 两个杂兵、强制切阶段：
**0 异常、0 NaN、实体/hitbox/telegraph 无泄漏**（结束时全部归零），FX 峰值 391（上限 600）。
六个 Boss 逐一验证：`onDefeat` **各触发一次**，`hp=0`、`dead=false`、`act='down'`、
仍在实体表里、hitbox 与 telegraph 都已清空 —— 倒地不死，等关卡层弹生杀。

## 5. 我认为最难 / 最不公平的招（诚实版）

**最不公平：白衣 P3 的快剑（`b_kuaijian`）。**
起手 0.42 × windMul 0.86 = **0.36s**，就贴着下限。实测格开率 74%，
但那是在「玩家没在挥剑」的前提下；玩家一旦贪一刀，这三下就是白挨。
我的辩护是它每段只有 7 点伤害、而且**不是设计来给你格的** —— 它是逼你后撤的鞭子。
但如果 Lead 或玩家反馈说难受，**把它加到 0.50 是安全的**，不会伤到白衣的性格。

**第二不公平：刺客的「闪」。** 我已经从 0.46 提到 0.52，并且强制
**瞬移发生在起手式之前** —— 落地后仍有完整 0.52s。
即便如此，`windMul ≤ 0.8` 时格开率就掉到 33%。刺客请不要用低 windMul。

**曾经真的不公平、已经修掉的五处**（留档，免得以后有人改回去）：
1. **雨中刀「雨落」的落地砸**：起跳的起手式在他离地那一刻就结束了，
   落地的震波是一个全新的 hitbox，**完全没有前摇**（实测 0/4）。
   现在起跳时会再登记一道跟着他走的落地起手式（0.52s），落点就是他脚下。
2. **箭与冲撞**：telegraph 结束 ≠ 命中。飞行时间里玩家必须能继续读。
   现在机器人也按同样规则计时，实测穿杨 12/12。
3. **枪兵站在自己的射程外**：他维持 130px，而镇山原本只打 ±107。已扩到 ±150。
4. **力士的冲撞撞墙/刹车之后判定还活着**：`onAct` 里只把相位跳掉，
   跟随 hitbox 还会跟着后摇再活半秒 —— 人已经明明白白停在那儿了，玩家还会被打中
   （实测 56 帧）。现在停下的那一帧就杀 hitbox（崖边与撞墙都算），
   平地与崖边实测 0 帧，撞墙残留 2 帧（33ms，物理刹停与下一帧检测之间的不可消除间隔）。
5. **瞬移落点在墙里 → 实体永久卡死**（notes-E §6，E 在 tech.js 里踩过同一个）：
   `World.moveX/moveY` 只在「移动过程中」推出，已经重叠了是推不出来的。
   刺客的「闪」、孤影、白衣分身原本都直接写 `e.x/e.y`。
   现在统一走 `AI.blink(e, tx, ty)`（沿原路回退 6 档取第一个不重叠点，全不行就原地不动）。
   **构造性实测**：把玩家摆在 1320–1490 那块实心台阶右侧，让落点正好落进台阶 ——
   旧写法 2400 帧里 **283 帧卡在实心里（最长连续 32 帧）**，换成 `AI.blink` 后 **0 帧**；
   183 秒混战压力测试里也是 0。
6. **白衣的分身把本体的出手额度吃光了**：`AI.attackers()` 原本把三个影也算进
   `maxAttackers`，导致 P3 本体几乎不出招 —— 那个阶段的主角反而是龙套。
   现在分身不计入全局额度，改由影自己排队（同时最多一个影出手）。
   修完 P3 本体四招齐发，同屏危险轨迹峰值仍是 2，格开率 39/46。

**我有多大把握窗口是公平的**：
- 起手式 ≥ 0.55s 的招（大部分）：**很有把握**，机器人在 0.45s 延迟下都能稳定格开。
- 0.42–0.52s 的快招：**中等**。它们全部集中在刺客与白衣/师兄的后半段，是刻意的难度。
- **唯一没把握的是「玩家自己在挥剑」这条线**。我用 `AI.playerLock()` 做了保护，
  但那是估算（普攻剩余按 0.26 / 0.36 估）。**如果 E 能暴露一个 `p.lockRemain()`，
  我这条闸就能从估算变成精确** —— 这是我唯一想向 E 要的接口。

### 6.1 `windMul` 按章推荐（**别低于 0.75**）

| 回 | windMul | 刀客破雨实际 | 意图 |
|---|---|---|---|
| 一 竹林 | **1.15** | 0.80s | 慢而夸张。玩家要在这里第一次注意到朱砂虚线 |
| └ **第一个刀客** | **1.00 + `only:['poyu']`** | **0.70s** | 决议 012 的教具，见下 |
| 二 客栈 | 1.05 | 0.74s | |
| 三 长河 | 0.95 | 0.67s | |
| 四 雪山 | 0.88 | 0.62s | |
| 五 藏经阁 | 0.85 | 0.60s | 战斗少，不必再紧 |
| 六 城楼 | **0.78** | 0.55s | 大杂烩，靠密度而不是靠快 |

Boss 自己会在阶段推进时调 `windMul`，**不要再从外面覆盖 Boss 的**。

**决议 012 · 第一回第一个刀客是全游戏的教具**，G 请照这一行摆：

```js
SJ.Enemies.spawn('daoke', x, y, { facing: -1, windMul: 1.0, only: ['poyu'] });
```

`only` 把他钉死成「只会破雨」，起手式正好 **0.70s**。
实测 60 秒：**只出破雨、出手 20 次、间隔约 2.9s、20 次全部打到了玩家身上**
（0.32s 反应的机器人 20/20 全格开）。
他不难，他清楚 —— 反复出同一招，让玩家有机会看见那道朱砂虚线；
打得中，所以读不出观势的玩家也能靠挨打攒残墨（12%/次，约 9 次触发一次「悟」）。
**后面的敌人才越来越快越有欺骗性。**

### 6.2 每种杂兵适合什么地形、几个一组

| 敌人 | 地形 | 组数 | 摆位要点 |
|---|---|---|---|
| **刀客** | 平地、窄道 | 1–3 | 第一回**只放一个**，前后留 300px 空地，让玩家有地方看清起手式 |
| **弓手** | **高台 / 平台上**（他会后跳，别放在坑边） | 1–2 | 放在玩家够不着的平台，逼玩家先处理近战或学穿杨。**绝不要单独放**——他一个人只会磨 |
| **枪兵** | 平地 | 1–2 | 镇山打 ±150 且两侧都打，**脚下要有 300px 连续平地**，否则玩家没地方跳 |
| **力士** | 宽平台、走廊 | 1 | 冲撞要 340px 助跑；放在窄台上他会停在边缘（有防坠崖判定），显得呆 |
| **僧人** | 门口、桥头、**必经的窄处** | 1 | 他就是一道门。旁边配一个弓手，逼玩家不能站着磨 |
| **刺客** | 有落差、有掩体的地方 | 1–2 | 瞬移会找玩家背后的地面；**空中平台多的地方他最好看** |
| **提灯人** | 雪山（四回）、藏经阁走廊 | 1–3 | 他是光源。`e.light.r=168`，死后 1 秒内熄灭 —— 可以拿他当「必须留手的照明」做谜题 |

**组合建议（DESIGN 要的「威胁在组合不在单体」）**：
- **弓手（高台）+ 枪兵（地面）** —— 第三回的招牌组合。玩家必须在镇山的间隙里躲箭。
- **僧人（正面）+ 弓手（后排）** —— 逼出无锋，或者逼玩家绕后（僧人背后不挡）。
- **刺客 ×2** —— 只在第六回用。两个刺客同时闪到背后是全游戏最凶的一组。
- 同屏危险起手式峰值被 `AI.maxAttackers = 2` 压住，所以**一波放 4–5 个杂兵是安全的**，
  不会出现满屏朱砂虚线。要更混乱可以自己调高这个数（不建议超过 3）。

### 6.3 Boss 房的最小尺寸

| Boss | 最小宽 | 理由 |
|---|---|---|
| 雨中刀 | 900 | 横云断前冲 560×0.3s ≈ 170px，加两边余量 |
| 铁笛先生 | 1100 | 音波要飞得起来；玩家要有 300px 的近身路 |
| 渡口老翁 | 1000 | 横扫射程 220，旋风扫 ±150 |
| 白衣 | **1400** | 三个分身按 ±150 摆开，本体可能在最边上，屏幕（960）要装得下真假对比 |
| 守阁人 | 800 | 震脚击退 420，玩家要有地方被震回来 |
| 师兄 | 1200 | 孤影 + 镇山 + 横云断都要位移 |

**地面必须连续**。所有 Boss 都有防坠崖判定，站在坑边会原地不动，看起来像卡住了。
需要平台的话请放在**头顶**，不要在地面开洞。

### 6.4 几个容易踩的点
1. `SJ.Bosses.spawn` 之后**记得赋 `e.onDefeat`**，否则 Boss 倒地就没有下文了。
2. 箭（`tag:'arrow'`）与音波（`tag:'wave'`）被穿杨弹回后 **`team` 会变成 `'player'`**。
   关卡判定「杂兵清空了没有」请用 `SJ.Ent.by('foe').filter(e => e.def)`，别数 team。
3. 白衣的影（`id:'baiyi_ying'`）也在 `Ent.by('foe')` 里，**别把它算进遭遇战计数**。
4. `SJ.AI.maxAttackers` 是全局的；如果某一波你想要更混乱，改完**记得改回来**。
5. 每个敌人两次起手式之间有 **0.9s 的强制空档**（`e.gap`，notes-E §5）：
   完美观势给敌人 0.9s 硬直，而玩家三连全程 0.62s —— 空档小于 0.9s，
   格挡成功就换不来一套连段，「做对了却没有奖励」是最伤的一种设计。
   实测加了这道闸之后杂兵 60 秒仍然出手 17–22 次，**没有变温吞**。

## 7. `dev/enemy.html` 怎么用

`python3 -m http.server` 之后开 `dev/enemy.html`。
（页面用 `document.write` 给每个 `src` 加了时间戳版本号 —— 改完 src 直接刷新就是新代码，
不会吃到浏览器缓存。自动化迭代时这一条很要命。）

- 左键点面板生成任意杂兵 / Boss / 预设编组；数字键 1–7 也能生杂兵
- `hitbox` / `轨迹常显` / `锁AI` / `无敌` / `满墨` / `清场`
- `P1 P2 P3` 强制切 Boss 阶段，`回满血` 重来
- **起手式倍率**滑杆 = `windMul`，实时作用于场上所有敌人
- **反应机器人**：开 → 它会在起手式出现 L 秒后按住 K，面板实时显示每一招的
  `格开/总数`。`打印` 把表打到控制台。滑杆调 L（0.10–0.60s）
- `H` 隐藏面板（截图用）、`R` 复位玩家、`Q` 打印统计
- `window.T` 是给浏览器自动化用的把手：`T.spawn / T.clear / T.foes / T.stats / T.D / T.err`

配合 `SJ.Game._step()` 可以完全确定性地推帧，本文档 §4 的所有数字都是这么测出来的。

## 8. 遵守情况自查（决议 001 / 005）

- ✅ **每帧维护 `e.figOpts`**（`AI.figure`，含 `pose/weapon/facing/scale/vx/vy/key`）。
  身法残影、刺客瞬移、孤影、白衣分身全部依赖它，都实测过。
- ✅ **pose 约定**：只用 `SJ.Figure.pose()` 出来的姿势，没有手搓角度，不会违反屈膝负/屈肘正。
- ✅ **`telegraph.path` 原点**：相对 owner 中心，x 按 facing 镜像，y 向下为正。
  截图验证过刀客破雨、白衣遍照、守阁人守势 —— 轨迹方向与实际判定一致。
- ✅ **完美观势的硬直走 `hurt(0, src, {parried:true, stun:0.9})`**。
  combat.js 会**走两条路进来两次**（`p.onParry` 与 `strike` 各调一次 `Combat.stun`），
  我的 `hurt` 对 `parried` 做了幂等处理（取最大值，不叠加、不掉血、不击退），
  并且会杀掉本人所有活着的 hitbox 与 telegraph —— 不然格挡完还会被同一刀打中。
- ✅ **没有重复实现点燃与 stun**：提灯人只传 `type:'fire'`，DoT 在 combat.js。
- ✅ 只动了自己的四个文件：`src/entity/{ai,enemies,bosses}.js`、`dev/enemy.html`、本文件。
